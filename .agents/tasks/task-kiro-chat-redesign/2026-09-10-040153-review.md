# Kiro-style chat redesign with attach/repo/web-search context and LAN model sharing

Six commits redesign the chat surface into a bottom-anchored Kiro-style composer with inline controls, add a welcome-screen landing gated on `activeConversationId`, nest Conversations under the Chat nav item, and ship three real context features (file/image attach with a vision gate, repository context, pluggable web search defaulting to Tavily) plus local-network model sharing (consume peers, share/serve seam, discovery seam). Thirteen new Tauri commands are added with `_inner` factoring, `generate_handler!` registration, IPC wrappers, and hand-mirrored camelCase TS types. Context of every kind rides inside the existing user-message `content` String, so `run_turn` / `send_message` semantics are untouched. The additive `AppConfig.web_search` / `AppConfig.model_sharing` fields are `skip_serializing_if` their default, keeping older configs loadable.

Watch for: nothing blocking. The image-attach path is a vision-GATED note, not real multimodal bytes (documented follow-up, correctly implemented — *confirmed*); the secret-persistence "no secret found" diagnostic is a recorded pre-existing follow-up, not introduced here (*confirmed*); LAN discovery and live share binding are stubbed and user-only by design (*confirmed*). One minor privacy nuance worth an explicit note: a peer added at a *loopback* base_url would classify as local (*confirmed*), which is benign because a loopback peer is on-host, but see below.

**Verdict**: APPROVED

## High-level view

The command surface is complete and symmetric: all 13 new commands have a `#[tauri::command]` wrapper, an `_inner` body, `generate_handler!` registration in `lib.rs`, an IPC wrapper in `commands.ts`, and a camelCase TS view type whose fields match the `#[serde(rename_all = "camelCase")]` Rust structs exactly. Secret hygiene holds throughout — web-search and peer keys flow in and are stored as `SecretRef`, never returned; `WebSearchError` drops the HTTP body to avoid echoing the key.

The LAN privacy boundary is real. `local_provider_ids` admits a `GenericOpenAI` row into the locality set only when its base_url is loopback, and a peer is stamped at its (non-loopback) LAN base_url, so a `LocalOnly`/`Confidential` conversation is correctly excluded from routing to a peer — pinned by `network_peer_is_excluded_from_local_provider_ids`. The share server likewise re-exposes only `local_provider_ids` models, so a peer is never re-shared onward and cloud models are never exposed.

Web search degrades gracefully and never hangs: an unconfigured or failing search returns a clear `CommandError`, and the composer shows a `role="status"` notice and still sends the plain message. The vision gate genuinely blocks: a non-vision effective model shows a non-fatal notice and does not attach the image. Attachment and web-search context are both capped at 128 KiB with the user's draft always preserved in full.

The composer preserves the v0.7.4 invariants that prior CI cycles cared about: the IME-safe Enter/Shift+Enter handler, the `sendState==='failed'` `role="alert"`, and the Stop button's disabled/labelled semantics are unchanged. `InlineModelControl` reads and writes the single shared `pendingOverride` store value rather than holding its own copy, and `RoutingModeToggle` keeps its radiogroup + zero-models-suppression so exactly one no-models guidance block renders.

Test-mock discipline matches the known failure classes: `app.test.tsx` `routeInvoke` covers all 13 new commands, `webSearchEnabled`/`attachments` are initialized in the `beforeEach` reset and `resetStores` helpers, `@tauri-apps/plugin-dialog`'s `open()` is mocked where used, and the settings tests mock the on-mount reads. Per-crate `cargo fmt --check` passes for all four touched crates.

### Command surface parity and secret hygiene

All thirteen commands (`read_text_file`, `read_file_base64`, `list_repo_files`, `set_web_search_provider`, `get_web_search_config`, `clear_web_search_provider`, `run_web_search`, `add_network_peer`, `list_network_peers`, `remove_network_peer`, `set_model_sharing`, `get_model_sharing`, `discover_network_peers`) appear in the `generate_handler!` block in `lib.rs`, each with a thin `#[tauri::command]` wrapper over an `_inner` body, an IPC wrapper in `ipc/commands.ts` invoking the matching snake_case command name with camelCase args, and a mirrored TS view type. The view structs (`FileContentView`, `FileBinaryView`, `RepoFileEntry`, `RepoListing`, `WebSearchConfigView`, `WebSearchResultView`, `NetworkPeerView`, `ModelSharingView`, `DiscoveredPeerView`) all carry `#[serde(rename_all = "camelCase")]` and their fields match the TS interfaces one-for-one (e.g. `byte_len`→`byteLen`, `rel_path`→`relPath`, `mime_type`→`mimeType`, `has_api_key`→`hasApiKey`, `base_url`→`baseUrl`).

No command returns key material. `set_web_search_provider` stores the plaintext under the stable `web-search` handle and returns only `{ kind, hasApiKey, maxResults }`; `run_web_search` resolves the key core-internally at search time; `WebSearchError::from_provider_error` deliberately drops the `HttpStatus` body (which could echo request context) and keeps only the numeric status, asserted by `error_is_display_safe_and_key_free`. A peer's optional key is stored as a `SecretRef` under the peer id and `add_network_peer` deletes any prior secret on a keyless re-add so nothing is orphaned.

### LAN peer off-host privacy exclusion

```
add_network_peer(base_url = "https://192.168.1.50:11435/v1")
   → ProviderKind::GenericOpenAI, id = network-peer-<hash>
   → check_provider_base_url: non-loopback plaintext → WARN (not blocked); link-local/metadata → REJECT

local_provider_ids(configs):
   GenericOpenAI is local ⇔ base_url is loopback
   peer base_url is non-loopback ⇒ EXCLUDED
   ⇒ LocalOnly / Confidential conversation never routes to the peer
```

This is the load-bearing privacy property and it is real, verified by `network_peer_is_excluded_from_local_provider_ids`. The one nuance: a peer added at a *loopback* base_url is a loopback `GenericOpenAI` row and would be admitted to `local_provider_ids` — but such a peer is genuinely on-host, so treating it as local is correct rather than a leak. Worth a one-line comment so it reads as intentional. The share server's `local_shared_models` reuses the same `local_provider_ids` set, so a peer is never re-shared onward and cloud models are never exposed to the LAN.

### Web search fallback: visible and still-sends

`run_web_search_inner` returns `CommandError::invalid("web search is not configured")` when no provider/key is set, and maps a provider failure to a display-safe `CommandError`. In `Composer.submit`, the search runs on the raw draft before send; on any throw it sets a `role="status"` notice ("Web search unavailable: … Sending without web results.") and proceeds to `void sendMessage(assembled)` with the assembled attachment context intact. There is no path where a failed or unconfigured search blocks or drops the message. `assembleWebSearchContent` returns `content` unchanged on an empty result list, so a zero-hit search adds no noise.

### Attach, repository context, and the vision gate

`effectiveModelSupportsVision` resolves the effective model as override → pin → first-available and returns its `capabilities.vision` (false when there are no models). The composer's attach handler routes image paths through this gate: when vision is false it sets the "This model doesn't support images" notice and does *not* attach, exercised by the chat test that seeds a non-vision model and asserts zero attachments. Text files go through `read_text_file` (256 KiB cap, UTF-8 only, binary-by-extension rejected, cap re-checked after read since `metadata.len()` can lag); images through `read_file_base64` (4 MiB cap, MIME guessed from extension). `list_repo_files` walks with an explicit stack (bounded, no recursion), skips VCS/dependency/build dirs and binary extensions, caps at 500 entries and flags `truncated`. The failure-prone pure helpers live in `domain::file_context` with RFC-4648 base64 vectors and cap/skip/mime unit tests, so they are `cargo test`-covered offline even though `tauri-app` is CI-only.

`assembleContent` prepends a bounded, delimited block capped at `MAX_CONTEXT_BYTES` (128 KiB), adding sections until the next would exceed the cap and then emitting a truncation marker; the draft is appended after the block and never counted against the cap, so a large attachment can't eat the user's message. Attachments are held in the conversations store and cleared only on a *successful* send (`sendMessage` sets `attachments: []` in the success branch, leaves them on failure for retry), mirroring how the transient override is consumed once.

### Composer preserves v0.7.4 behavior

The `onKeyDown` handler still guards `event.nativeEvent.isComposing || event.keyCode === 229` before treating Enter as send and returns early on Shift+Enter, so IME candidate-commits and newlines are preserved. `sendState === "failed"` still renders the `role="alert"` "Failed to send:" line. Stop stays disabled unless a message is streaming and is titled "Stop (cancellation is not yet available)", matching the honest no-cancel-seam semantics. `InlineModelControl` subscribes to `pendingOverride`/`setPendingOverride` — the same shared store value the send path consumes — so there is no duplicated override ownership, and it renders a single `NoModelsEmptyState` while `RoutingModeToggle` suppresses its own picker when models are empty, preserving the single-guidance invariant.

### Test-mock completeness

`app.test.tsx` `routeInvoke` has a case for every new command with a well-formed shape (including `get_route_explanation` returning `rationale: null` so no info icon spuriously shows). The `beforeEach` reset and the two in-test `setState` calls that fully reset the store carry `webSearchEnabled: false` and `attachments: []`; the mid-test `setState` calls that seed one field rely on Zustand's shallow merge, which is correct. `chat.test.tsx` mocks `@tauri-apps/plugin-dialog`'s `open()`, captures and restores the real providers `load()` (since the composer's Refresh icon calls it), and resets the new store fields. `settings.test.tsx` mocks `get_web_search_config`, `list_network_peers`, and `get_model_sharing` for the sections' on-mount reads. Because Settings defaults to the Providers section, the WebSearch/NetworkSharing on-mount reads only fire when their nav item is clicked, and the tests mock accordingly.

### Additive config and forward compatibility

`WebSearchConfig` and `ModelSharingConfig` are each `#[serde(default, skip_serializing_if = "…is_default")]` on `AppConfig`, with per-field defaults and an `is_default` that matches the constructed default, so an older config loads unchanged and a default (web search unconfigured / sharing off) is omitted from the serialized JSON. Round-trip and omission tests cover both. The sharing port defaults to 11435, chosen clear of Ollama 11434 and LM Studio 1234; `set_model_sharing` rejects port 0 and reports a visible `ShareServerStatus` (Running/Unavailable) rather than hanging on a taken port.
